# player-core — этап 1

Cargo Workspace из трёх крейтов: `core-types` (типы и контракты),
`resolvers` (независимые сетевые адаптеры), `cli-test` (ручная диагностика).
Нативные async-трейты, Tokio, Reqwest + Rustls. Нет Tauri, аудиодвижка,
внешних исполняемых программ, сохранения токенов на диск.

## Проверка

Из корня workspace:

```powershell
cargo check --workspace
```

Статус проверки в среде создания: команда была вызвана, но PowerShell
не обнаружил `cargo`; в стандартных каталогах Rust toolchain также не найден.
Компиляция и запуск CLI пока **не подтверждены**. Нужен установленный
Rust stable; на Windows — также инструменты сборки для выбранного toolchain.

CLI принимает Spotify track URL/URI/ID либо поисковую строку.
Для списка метаданных плейлиста: `cli-test --playlist <Spotify playlist URL>`.
Для трека выводит JSON-метаданные и результаты обоих резолверов,
запущенных параллельно через `tokio::join!`. Ошибка одного сервиса
не скрывает результат другого. Код завершения 1 — ошибка метаданных
или отсутствие обоих потоков; 0 — хотя бы один поток найден.

## Контракты

- `MetadataProvider::track` / `playlist`, `StreamResolver::resolve`.
- ID имеют префикс провайдера. Длительность — миллисекунды,
  битрейт — бит/с, `expires_at` — Unix timestamp в секундах.
- `stream_url` — прямой медиа-URL **или URL HLS-манифеста**, не веб-страница.
  Для HLS будущий плеер должен поддерживать плейлисты и сегменты.
- Допуск длительности включительный: **±3500 мс**. Неизвестная или
  нулевая длительность не принимается. Для YouTube окончательный
  фильтр использует точную длительность аудиопотока, а не округлённую
  длительность из поиска. Itag 251 имеет приоритет, затем прочий Opus, AAC.
- SoundCloud: публичный client_id из JS, обновление при 401/403,
  Opus перед MP3, HLS/Progressive; previews и ограниченные треки исключены.
- Подписанные URL временные; повторно разрешайте трек при истечении срока.
  `None` в `expires_at` означает неизвестный срок, а не бессрочную ссылку.

## Ограничения публичных сервисов

Spotify embed отдаёт точный `duration`, артистов и варианты обложки;
выбирается максимальная опубликованная площадь изображения.
ISRC и альбом обычно **отсутствуют** в embed. Адаптер пытается дополнить
их через Web API с анонимным токеном из embed. Если Spotify закрывает
доступ, `isrc`/`album` остаются `None` — данные не подменяются.
Поиск требует доступного анонимного Web API и может вернуть 401/403.
Плейлист получает страницы Web API либо треки полного embed;
усечённый плейлист/неизвестный total не выдаётся за полный.

YouTube использует `rustypipe`, но вызов внешнего `rustypipe-botguard`
**отключён** (`no_botguard`). Если YouTube требует PO token, авторизацию
или блокирует IP, поток может быть недоступен. URL проверяется GET-запросом
с Range без скачивания тела; успешный запрос не гарантирует доступность
всех будущих сегментов или работу с другого IP. DRM не поддерживается.

Это недокументированные публичные интерфейсы: изменения схем, геоблокировки,
лимиты и запреты анонимного доступа возвращаются как `ResolverError`.
Никакие платные API-ключи не нужны, но безусловный доступ не гарантируется.
Совпадение запроса и длительности — эвристика, не аудиоидентификация.

`rustypipe` распространяется по GPL-3.0; манифесты workspace используют
совместимую GPL-3.0-or-later. Это важно учитывать при дальнейшем распространении.
Проверка Android/Tauri и воспроизведение не входят в этот этап.
